第一部分 — 从源代码到可执行文件（slides 8–14）

Slide 8–9 — What happens when you run a program？

整个第一部分由一个最简单的程序 hello.c 串起来：

#include <stdio.h>

int main(void) {
    printf("hello, world!\n");
    return 0;
}

逐行解读：

  • #include <stdio.h> —— 引入标准 I/O 头文件，里面声明了 printf。这只是声明，不是实现——实现住在 libc 里，要等链接阶段才接上。
  • int main(void) —— C 程序的入口；返回 int（给 shell 的退出码），不接参数。
  • printf("hello, world!\n"); —— 调用 libc 的 printf，把字符串送到标准输出。\n 触发行刷新。
  • return 0; —— 退出码 0 表示成功。

讲师把它叫 "high-level" 是因为人读得懂；但 CPU 不认 C，要先编译成机器指令。把它跑起来要四个阶段：预处理 → 编译 → 汇编 → 链接。一条命令背后：

$ gcc -o hello hello.c

这一句把四步全做了。下面四张 slide 把它拆开看。

Slide 10 — 阶段 1：Preprocessing（预处理）

预处理器只做文本替换，处理所有以 # 开头的指令、剥掉注释：

  • #include <stdio.h> 整个被替换为 stdio.h 的内容（递归展开里面的 #include）。
  • #define 宏被就地展开。
  • #if / #ifdef 条件分支按平台/构建参数选择。
  • // ... 和 /* ... */ 注释被删掉。

想看预处理结果：

$ gcc -E hello.c > hello.i

这一行把 hello.c 经预处理后的纯文本写到 hello.i。关键点：到这一步还全是 C 代码，只是被"展开 + 清理"过。

Slide 11 — 阶段 2：Compilation（编译）

编译器把预处理过的 hello.i 翻成汇编语言（人能读的 CPU 指令文本）。

  • 为什么停在汇编、不直接出二进制？—— 汇编是中间形式，方便我们在性能优化时读出来检查"编译器到底生成了什么指令"。这门课后面调 SIMD 时会反复看汇编。
  • 它还提供了统一出口：C、C++、Fortran 不管前端是谁，到了汇编层全是一样的指令集（x86-64 / aarch64），后续两个阶段对它们一视同仁。
$ gcc -S hello.i -o hello.s   # 只编译到汇编，产物是 hello.s

Slide 12 — 阶段 3：Assembly（汇编）

汇编器把 hello.s 的文本汇编翻成真正的二进制机器指令，打包成 relocatable object file（可重定位目标文件，.o）：

$ gcc -c hello.c   # 只编译到 .o，产物是 hello.o

"Relocatable" 的意思：里面对外部符号（如 printf）的地址还没填上，等链接阶段决定。

对 hello.o 反汇编一下，能看到 main 函数被编码成 23 字节：

$ objdump -d hello.o
0000000000000000 <main>:
   0: 48 83 ec 08      sub    $0x8,%rsp
   4: 48 8d 3d 00 00 00 00   lea    0x0(%rip),%rdi   # b <main+0xb>
   b: e8 00 00 00 00         call   10 <main+0x10>
  10: 31 c0                  xor    %eax,%eax
  12: 48 83 c4 08            add    $0x8,%rsp
  16: c3                     ret

逐行说一下（不需要背，了解结构即可）：

  • sub $0x8,%rsp —— 给栈腾 8 字节空间（函数调用前的对齐）。
  • lea 0x0(%rip),%rdi —— 把 "hello, world!\n" 字符串的地址装到 rdi（第一个参数寄存器）。注意操作数里的 0x0 —— 这是占位符，等链接器把真实地址回填进来。
  • call 10 ... —— 调用 printf。这里的目标地址也是 0 占位，等链接器解析 printf 符号后填上。
  • xor %eax,%eax —— 把返回值寄存器清零（对应 C 里的 return 0，xor reg,reg 是清零的惯用写法，比 mov $0 短）。
  • add $0x8,%rsp —— 还栈。
  • ret —— 从 main 返回。

这一步之后，代码已经是机器指令，但有"洞"——下一步链接填洞。

Slide 13 — 阶段 4：Linking（链接）

printf 不住在我们的 hello.o 里，它住在 C 标准库提供的 printf.o（实际上是 libc.so 的一部分）里。链接器负责把两个 .o"焊"成一个可执行文件，把上一步那些 0x0 占位真正填成 printf 的最终地址：

$ gcc -o hello hello.o printf.o

实际编译我们从来不用显式写 printf.o——它是标准库的一部分，编译器自动找。但原理就是这样。后面课里用 OpenMP / MPI 库的时候，-fopenmp / -lmpi 这些参数就是在告诉编译器"该链哪个库"。

💡 编译流水线四步总结：
  • 预处理（.c → .i）：纯文本展开
  • 编译（.i → .s）：C → 汇编
  • 汇编（.s → .o）：汇编 → 机器指令（带空洞的 object）
  • 链接（.o + libs → 可执行）：填洞，合成一个完整二进制

Slide 14 — 当你执行 ./hello 那一瞬间

从你敲下 ./hello 到屏幕上出现 hello, world!，背后发生了：

  1. 字符进入 shell：你敲的每个字符进入键盘缓冲区，由 OS 一个个送进 shell 的内存。
  2. 回车触发执行：shell 知道你说完了，准备启动 hello。
  3. 装载 (load)：shell 让 OS 把 hello 文件的代码段和数据段（含 "hello, world!\n" 字符串）从磁盘搬到 main memory。
  4. 跳转执行：CPU 的 PC（program counter）指向 main 的第一条指令，开始一条一条执行。
  5. 字符送到显示器：执行到 printf 时，字符从 memory 经 register file 一路送到显示设备。

这就把第一部分接到了第二部分——main memory、register file、PC、bus这些词后面要展开。

第二部分 — 计算机体系结构（slides 15–26）

Slide 16–17 — 为什么要学硬件 + 典型组成

讲师的论点：性能 = 算法 + 硬件。"硬件细节会变，但性能原则不变"——所以这一节学的不是 Intel 某代具体怎么连线，而是一切现代 CPU 都有的四类组件：

  • Main memory（主存）：临时存储
  • Processor（CPU）：执行单元
  • Buses（总线）：电气通道
  • I/O devices：与外界连接

Slide 18 — Main Memory

  • 临时存储：断电就丢。
  • 同时存指令和数据（这是 von Neumann 架构的定义之一）。
  • 物理上是 DRAM（Dynamic RAM）——"Dynamic" 是因为每个存储单元（1 个晶体管 + 1 个电容）的电荷会泄漏，必须定期刷新，所以 DRAM 有刷新频率（MHz 量级）。
  • 逻辑上是一个线性字节数组，每字节有唯一地址（从 0 开始）。地址就是数组下标。
  • 地址空间被指针/寄存器位宽限制：
    • 32 位系统：2³² = 4 GiB 上限
    • 64 位系统：2⁶⁴ ≈ 16 EiB 上限（实际芯片不会真实现到 64 位，目前一般 48–52 位）

Slide 19–21 — Processor / CPU 的工作模型

核心组件

  • Program Counter (PC) —— 一个字宽寄存器，里面装"下一条要执行的指令的内存地址"。CPU 上电开始就反复做：取 PC 所指指令 → 执行 → 更新 PC。
  • Register file —— 一小组字宽寄存器，CPU 直接操作的数据全部从这里来。访问 register 比访问 main memory 快 10–100 倍。
  • ALU（算术逻辑单元） —— 计算新值（加减乘除、按位运算）和新地址。

ISA：指令集架构

  • RISC（Reduced Instruction Set Computer）：指令少且简单，每条等长（ARM、RISC-V）。
  • CISC（Complex Instruction Set Computer）：指令多、变长、单条可以做复杂操作（x86）。
  • 现代 x86 内部其实把 CISC 解码成 micro-ops 后用 RISC 风格的流水线执行——但程序员仍按 CISC 写。

四种基本操作（slide 21）

操作含义
Load把 main memory 里的一个字节/字搬到 register（覆盖原 register 内容）
Store反过来：把 register 里的值写回 main memory
Moveregister ↔ register，不碰 main memory
Compare把 register 和 0（或与另一个 register）比较，结果存进 flag

真实 ISA 有上百条指令，但本质上都能拆成这四类的组合。

Slide 22–23 — Buses & I/O Devices

Buses（总线）是连接 CPU、memory、I/O 的电气通道，每次传"一个 word"。

  • Word size = 一次传几个字节，是系统最基本的参数。今天主流：32 位（4 B）或 64 位（8 B）。
  • Bandwidth = 单位时间能传的字节数。现代 CPU ~400 GB/s，GPU 数倍于此——slide 提了这个对比是为了 foreshadow 后面"GPU 为什么强"的讨论：GPU 内存带宽就是比 CPU 大得多，因为要喂上千个核。

I/O 设备通过 controller（板载芯片）或 adapter（插卡，如 GPU 走 PCIe）接到 I/O bus。它们的角色只是把字节从 I/O 设备搬到 bus 上。

Slide 24–26 — Von Neumann 架构 & 它的瓶颈

Von Neumann 的三件套

  1. Main memory（存指令和数据）
  2. Processor
  3. Interconnect / bus（在两者之间搬数据）

"指令和数据都从同一个 memory 经同一根 bus 进 CPU"——这就是 von Neumann。

这个模型缺什么？（slide 25）

  • I/O 设备（这一步课里加上了）
  • memory 被简化得太极端——真实系统是多层的 memory hierarchy（slide 27 之后展开）

Von Neumann Bottleneck（slide 26）

由于 CPU 和 memory 分开、之间只有一根 bus，数据搬运速度成为整体性能上限。讲师用一个工厂比喻：

  • Warehouse（主存）→ Traffic（总线）→ Factory（CPU）
  • 当 traffic 堵了，factory 工人就空闲（CPU stall）。

两个量化这个瓶颈的指标：

  • Latency（延迟）：发出请求到响应到达的时间。物理决定——管道越长越慢。
  • Bandwidth（带宽）：单位时间能满足多少请求。可以通过重叠多个 in-flight 请求提高，所以 bandwidth 不只是 latency 的倒数。

这两个概念在 slide 74 还会专门展开。

第三部分 — Memory Hierarchy & Caches（slides 27–36）

Slide 27–29 — Library Paradigm & Caches 的本质

图书馆比喻

你去图书馆写论文：不会每读一句就跑去书架取一次，而是把一摞当下要用的书搬到桌上，再展开读。书架 = main memory；桌子 = cache。这就是 cache 的全部哲学。

三层 cache（slide 29）

  • L1：最小、最快、最近 ALU。一般每个核独占。
  • L2：中间层，256 KB – 几 MB，可能私有也可能小组共享。
  • L3 (LLC, Last-Level Cache)：靠近 DRAM，几 MB 到几十 MB，所有核共享。

Cache 不是单独的"额外内存"——它是把 main memory 里正被访问的那一小片镜像到更近 / 更快的 SRAM 上。程序员不直接管它（硬件管），但代码写得好不好会决定命中率。

Slide 30–31 — 两台真实机器的拓扑

用 lstopo（hwloc 工具集）把机器的"层级"画出来。

左：Apple M2 Pro

  • 异构核：4 个性能核（L1d/L1i 128/192 KB，共享一块 16 MB L2）+ 4 个能效核（更小 cache，共享 4 MB L2）。
  • 没有 L3，L2 直连内存——Apple 的设计选择。
  • 整机 3442 MB（这是某个示例机型）。

右：Intel Xeon Platinum 8124M（CS 2050 集群的节点）

  • 1 个 socket，18 个物理核，每核 2 超线程 → 36 个逻辑 PU。
  • 三级 cache：每核 32 KB L1d + 1 MB L2（私有），共享 25 MB L3。
  • 69 GB NUMANode = 这颗 CPU 直连的 RAM。

读这种图的诀窍：从下往上 = 从快到慢、从私有到共享。L1 私有 → L2 私有 → L3 共享 → DRAM 共享。所有"cache coherence"（缓存一致性）问题的根源就是 L1/L2 私有但数据在共享层得保持一致。

Slide 32–33 — L1d vs L1i & Latency 数表

为什么 L1 分两套？

  • L1d（data）和 L1i（instruction）物理分开。
  • 原因：指令和数据的访问模式截然不同（指令几乎是顺序读，数据可能乱跳），独立设计 cache + 流水线效率更高。
  • L2 / L3 是 unified（数据指令混着装），因为这两层主要是过滤 L1 miss，不需要再分。

Latency 数表（要背的）

层级位置延迟（周期）由谁管

L1 cacheon-chip4硬件
L2 cacheon-chip10硬件
L3 cacheon-chip50硬件

关键对比：register vs DRAM 差 200×；DRAM vs disk 差 500×。跨一层就是数量级，所以让访问尽量命中上层是写高性能代码的核心动作。

Slide 34–36 — 为什么不用一个大 cache 就行了？

为什么要多层？

  • SRAM（cache 用的）单 cell 要 6 个晶体管 + 高功耗；DRAM 单 cell 只要 1 个晶体管 + 1 个电容。SRAM 每字节贵 50–100 倍。
  • 所以"又快又便宜又大"做不到——只能分层折中：上层小而快（贵），下层大而慢（便宜）。
  • 自 1985 年以来，DRAM 每 MB 的成本降了 44,000×，但访问时间只快了 10×——这就是为什么 memory wall（CPU 越来越快、memory 跟不上）始终存在，cache 的重要性反而越来越大。

第四部分 — Locality 原理 & 矩阵示例（slides 37–47）

Slide 37 — Principle of Locality

"高性能代码用 locality" —— 两种 locality：

  • Temporal locality（时间局部性）：刚用过的数据，很快还会再用。例：循环里反复读 sum。
  • Spatial locality（空间局部性）：刚用过的数据旁边那块很快会被用。例：顺序遍历数组。

整个 memory hierarchy 都假定了 locality 是真的——cache 一次拉一条 64 B 的 cache line，就是赌"你既然要 v[0]，多半也要 v[1]..v[15]"。

Slide 38–40 — Temporal vs Spatial Locality（用循环演示）

Slide 38：基本求和

int sum = 0;
for (int i = 0; i < N; ++i) {
    sum += v[i];
}
  • sum —— 每次循环都读+写一次，极强 temporal locality（多半被编译器搬进寄存器）。
  • v[i] —— 顺序访问，极强 spatial locality（每条 64 B cache line 装 16 个 int，前 15 次访问都是 cache hit）。

Slide 39：哪种嵌套更合理？

// 左：外层 loop，内层 i
for (int loop = 0; loop < 10; ++loop) {
    for (int i = 0; i < N; ++i) {
        ... = ... v[i] ...;
    }
}

// 右：外层 i，内层 loop
for (int i = 0; i < N; ++i) {
    for (int loop = 0; loop < 10; ++loop) {
        ... = ... v[i] ...;
    }
}

右边好：对每个 v[i]，连续 10 次都读它——拿到桌上的"那本书"被反复使用，极强 temporal locality。左边每次扫完整个数组才回头，N 大的话 cache 已经被换走了。

Slide 40：stride-1 / sequential pattern

顺序访问 v[0], v[1], v[2], ... 叫 stride-1（或 unit stride）。一条 cache line 一旦载入，后面 15 次几乎免费——是最理想的访问模式。

Slide 41 — Strided Memory Access

访问每 k 个元素叫 stride-k：访问 v[0], v[k], v[2k], ...

  • k 越大，空间局部性越差。当 k 跨过一条 cache line（>16 个 int 或 >8 个 double），每次访问都触发一条新 cache line 加载——浪费 15/16 的带宽。
  • 极端 stride-N（N 是数组宽度）就是列遍历 row-major 矩阵，性能灾难。

Slide 42 — Row-major vs Column-major

所有 memory 本质上是一维字节数组。二维数组要选一种 linearization：

  • Row-major（C/C++）：先把第 0 行铺完再第 1 行——A[i][j] 在内存里是 A + i*ncols + j。
  • Column-major（Fortran，BLAS/LAPACK，MATLAB）：先列后行——A + j*nrows + i。

选哪个不影响正确性，但影响 locality：

  • Row-major 下 for i { for j { A[i][j] } } 是顺序访问（stride-1）。
  • Row-major 下 for j { for i { A[i][j] } } 是跨行访问（stride = ncols），cache 灾难。

这就是为什么把 BLAS 风格的 column-major 代码直接搬到 C 里跑会慢——访问模式和 cache 布局对不上。

Slide 43 — 两种二维遍历的对比（Code A vs Code B）

// Code A：行优先（先 i 再 j）
for (int i = 0; i < N; ++i)
    for (int j = 0; j < N; ++j)
        sum += A[i][j];

// Code B：列优先（先 j 再 i）
for (int j = 0; j < N; ++j)
    for (int i = 0; i < N; ++i)
        sum += A[i][j];

在 row-major 下：

  • Code A（i 外层、j 内层）—— 内层 j 增 1 就访问下一个内存位置，stride-1，cache-friendly。
  • Code B（j 外层、i 内层）—— 内层 i 增 1 就跨一整行 (N × 4 B)，stride-N，cache-hostile。

Slide 还给了一个等价的"一维写法"：

float *p = &A[0][0];
float sum = 0.0;
for (int i = 0; i < N * N; ++i)
    sum += p[i];   // 完全顺序，stride-1

说明 Code A 本质上就是这个——既然是 stride-1，写一层 / 两层循环对硬件没区别。

Slide 44–45 — 矩阵乘 C = AB 的两种循环顺序

同一个数学操作，循环顺序换一下，性能可以差几倍。两个实现：

// Implementation 1: i, j, k（"dot-product" 顺序）
for (int i = 0; i < N; ++i)
    for (int j = 0; j < N; ++j)
        for (int k = 0; k < N; ++k)
            C[i][j] += A[i][k] * B[k][j];

// Implementation 2: i, k, j（"行更新" 顺序）
for (int i = 0; i < N; ++i)
    for (int k = 0; k < N; ++k)
        for (int j = 0; j < N; ++j)
            C[i][j] += A[i][k] * B[k][j];

逐项 locality 分析（slide 45 的核心）

变量Impl 1（ijk）Impl 2（ikj）
C[i][j]对最内层 k 是不变的 → 编译器搬进 register，写一次（很好）对最内层 j 在变 → 每次都要 load + store（多了存操作）
A[i][k]对最内层 k 是 row-major 顺序 → 好（stride-1）对最内层 j 是不变的 → 搬进 register，最好
B[k][j]对最内层 k 是 row-major 下 stride-N → 灾难对最内层 j 是 row-major 顺序 → 好（stride-1）

结论：B 的访问模式决定胜负。Impl 2 在内层走 B 的连续元素（stride-1），cache 利用率高得多。这就是著名的 "ikj 顺序比 ijk 顺序快"——同一个矩阵乘，光换循环顺序就能差 3–10×。

Slide 46–47 — Cache 术语 & 64-byte cache line

术语含义
Cache block / cache linecache 之间搬运的最小单位，固定大小（64 B 是 Intel/AMD 的标准）
Cache hit请求的数据在 level k 里找到了
Cache miss没找到，必须从 level k+1 拉一整条 cache line 上来；拉上来要踢掉某条已有 line（victim），按 replacement policy（LRU / LFU / random）选谁出局
Hit / miss rate命中（或未命中）的比例
Miss penalty把 line 从 k+1 搬到 k 所花的时间

为什么 cache line 是 64 字节？

  • 一条 line 装得下：16 个 int/float（4 B），或 8 个 double/long（8 B）。
  • 64 字节起始地址必须对齐到 64 字节边界（n-byte cache line 在 n-byte 边界）。
  • 太小 → 不利于空间局部性（每次只载几个元素）；太大 → 装得少（不利于时间局部性）。64 B 是经验最优。

回到矩阵乘 Impl 1 的 B[k][j]：访问一次 B[k][j] 拉一条 line（含 8 个 double），但下一次 k 增 1 又跳到 B[k+1][j]——是另一条 line。8 个元素只用了 1 个，浪费 87.5% 带宽。这就是 slide 47 强调的"inefficient and wastes a lot of bandwidth"。

第五部分 — 手算 Cache Miss：Case A vs Case B（slides 48–67）

Slide 48 — 题目设定

设置一个最小的模型来手算 cache miss：

  • 数组 float A[8][8] = 64 个 float。
  • Fully-associative cache：4 个 cache block，每 block 装 4 个 float → 总共 16 个 float。
  • "Fully-associative" 意思是：一条 cache line 可以放进任意一个 block（没有"必须放第几个 slot"的约束）。这种 cache 命中率最理想，但实际硬件做不到这么大（一般是 set-associative）。
// Case A：j 在外层
for (int j = 0; j < 8; ++j)
    for (int i = 0; i < 8; ++i)
        sum += A[i][j];

// Case B：i 在外层
for (int i = 0; i < 8; ++i)
    for (int j = 0; j < 8; ++j)
        sum += A[i][j];

C 是 row-major：内存里依次是 A[0][0], A[0][1], ..., A[0][7], A[1][0], A[1][1], ... 一条 cache block 装 4 个 float，所以每半行是一个 block。

Slide 49–55 — Case A 演练（j 外、i 内 → stride-8 灾难）

7 张 slide 把 j 外、i 内的访问一步步动画化。关键节点：

  • j=0, i=0（slide 50）：访问 A[0][0]。Cache 空，cold miss。拉进 A[0][0..3] 这条 block。
  • j=0, i=1（slide 51）：访问 A[1][0]。这不在刚才那条 block 里（block 装的是 A[0] 的前 4 个），miss。拉 A[1][0..3]。
  • j=0, i=2（slide 52）：访问 A[2][0]，又是新 block，miss。
  • ...继续到 j=0, i=7（slide 53）：8 个不同 block 全是 miss。但 cache 只有 4 个 slot——所以从 i=4 开始已经在evict 之前的 block（capacity miss）。
  • j=1, i=0：访问 A[0][1]。理论上 A[0][1] 和 A[0][0] 同一条 block，但那条 block 早已被 j=0 后期挤出去了。又是 miss。
  • 整个二重循环结束（slide 55）：64 次访问 = 64 次 miss → hit rate = 0%。
💡 Case A 的核心病：内层 i 是跨行访问（stride 8），每次都跳到一条新 block；外层 j 切回来时之前的 block 已被换走，cache 完全没起作用。

Slide 56 — Case A 小结

  • C/C++ row-major
  • 访问模式 stride-8 → spatial locality 极差
  • 64 / 64 = 100% miss → 0% hit rate

Slide 57–64 — Case B 演练（i 外、j 内 → stride-1 完美）

同样手动走一遍，但循环顺序换了：

  • i=0, j=0（slide 58）：cold miss，拉 A[0][0..3]。
  • i=0, j=1（slide 59）：A[0][1] 已经在刚才那条 block 里 → HIT。
  • i=0, j=2（slide 60）：同 block → HIT。
  • i=0, j=3：同 block → HIT。
  • i=0, j=4（slide 61）：跳到 A[0][4..7]，新 block → MISS（再 cold）。
  • i=0 这一整行用完（slide 62）：8 次访问 = 2 miss + 6 hit。Cache 现在装着 A[0] 的两条 block。
  • i=1 行开始：又是 2 miss + 6 hit；然后 i=2 同样；... 直到 i=7（slide 64）。
  • 总计 8 行 × 2 miss = 16 miss，64 - 16 = 48 hit → hit rate 75%。
💡 Case B 的好处：内层 j 是顺序访问 → 一条 block 装 4 个元素，每 4 次访问只有第 1 次是 miss，剩下 3 次全 hit。

Slide 65–66 — Case A vs Case B 对照 + Cache/Block size 的取舍

Case A（j, i）Case B（i, j）
访问模式stride-8（跨行）stride-1（顺行）
Miss 数6416
Hit rate0%75%

同一段代码逻辑，循环顺序换一下，cache 命中率从 0% 飙到 75%。 这就是为什么前面 slide 36 说"aware of cache memories"是这门课最重要的一句。

Cache size / block size 怎么选（slide 66）

  • Cache 越大：hit rate 越高，但查找电路也越慢（hit time 变长）→ 所以 L1 必须小（4 周期）才能不拖累流水线。L1 < L2 < L3 是物理决定的，不能避免。
  • Block 越大：利于 spatial locality（一次拉一大片），但装得下的 block 数变少 → 对 temporal locality 高的程序不利。64 B 是经验上的甜点。

Slide 67 — Recap

  • 所有现代计算机都有 cache hierarchy，目的是用 locality 换 bandwidth。
  • 程序员意识到 cache 的存在 → 能写出快得多的代码。
  • 两类 locality：temporal（同一元素短期内反复用）、spatial（用了元素 i 也会用 i+1）。
  • 核心抽象：cache line / cache block。
第六部分 — 下一节预告：SIMD + GPU + Latency/Throughput（slides 68–78）

Slide 68–70 — SIMD Vectorization 引子

SIMD 是什么

Single Instruction, Multiple Data —— 一条指令同时对一向量数据做同样的操作。例如：vaddps zmm0, zmm1, zmm2 一条指令把两个 16 维 float 向量逐元素加，写到 zmm0。

Slide 69 的指令表（要识别后缀）

  • 后缀 ss = scalar single（单精度，1 个 float）
  • 后缀 sd = scalar double（双精度，1 个 double）
  • "scalar" 标量 → 这些是 SISD 指令；后面 ps（packed single）/ pd（packed double）才是真正的 SIMD（多个元素打包在向量寄存器里）。
  • 表里的"4/4"、"3/3" 是 latency/throughput（周期）：Skylake 上 add 要 4 周期出结果，但 throughput 也是每 4 周期一条（流水线吃满）；div 11/14 说明 div 在管线里非常慢。

Slide 70：x86 SIMD 的演进

  • MMX (1997) — 64 位向量（仅整数）
  • SSE / SSE2 / ... (1999–) — 128 位
  • AVX / AVX2 (2011–) — 256 位（Sandy Bridge / Haswell）
  • AVX-512 (2015–) — 512 位（Skylake 服务器 / Cannon Lake）

lscpu 看自己 CPU 支持哪一档——这是写 SIMD 代码的第一步。CS 2050 集群是 Skylake Xeon，支持 AVX-512。

Slide 71–73 — 为什么要 GPU

三句话讲清"为什么 GPU"：

  1. Moore's Law 卡住了：单核频率没法继续涨（功耗墙），只能多加核。
  2. GPU 天生是数据并行的：渲染像素就是对一大堆独立像素做同样的操作 → SIMD 友好。
  3. CPU vs GPU 是两种取舍：
CPU coreGPU core
"重"核：大 cache、多控制逻辑、低延迟"轻"核：小 cache、低时钟、专注算术
少而强（几十个核）多而弱（几千个）
面向 latency面向 throughput（需要超大内存带宽喂饱）

"more transistors dedicated to data processing"——GPU 把大部分晶体管花在 ALU 上，不花在 cache/分支预测上。

Slide 75 用工厂压机举例：

  • Workshop press（车间冲压机）= 低 latency：换模具快，能灵活处理不同零件，但单位时间产量低。
  • Continuous press（连续生产线）= 高 throughput：换模具贵，但一旦跑起来源源不断出零件。

Slide 76–77 — Latency vs Throughput 的量化例子（购物中心）

参数：

  • 电梯（elevator）：latency 8 s，capacity 8 人
  • 扶梯（escalator）：latency 15 s，2 lanes × 1 人/s = throughput 2 人/s

空购物中心（3 个人）

  • 电梯：8 s（直接上）
  • 扶梯：15 s 走完 + 第 2 个人 1 s 后到顶 = 16 s
  • → 电梯赢（人少，latency 主导）

满购物中心（3000 人）

  • 电梯：8 s + (3000−8)/8 × 16 s ≈ 5992 s（每 16 s 上一拨 8 人）
  • 扶梯：15 s + (3000−2)/2 ≈ 1514 s
  • → 扶梯快 4 倍（人多，throughput 主导）
💡 CPU 像电梯（少量任务时快），GPU 像扶梯（大量并行任务时快）。选哪个工具不取决于硬件强弱，取决于工作负载形状。

Slide 78 — SIMD vs SIMT

两个相似但不一样的术语，常混：

SIMDSIMT
名字Single Instruction, Multiple DataSingle Instruction, Multiple Threads
程序员视角一条指令，操作向量寄存器写"很多独立线程"，每个 thread 自己的 PC
常见硬件CPU 的 SSE / AVX / AVX-512NVIDIA GPU（warp = 32 threads 锁步）
本质显式暴露向量硬件把 SIMD 藏在 thread 抽象后面

关键洞察：SIMT 的 hardware 其实就是 SIMD。一组 32 个 CUDA thread（一个 warp）实际上在同一条 SIMD pipeline 上锁步执行；只是 CUDA 的编程模型让你假装每个 thread 独立，分支不一致时硬件会 serialize 各分支（branch divergence）。

📌 Q&A 补充要点（点击展开）
  • 编译四步谁产生什么？ Preproc → .i（C 源）；Compile → .s（汇编文本）；Assemble → .o（带未解析符号的机器码）；Link → 可执行（符号全填上）。
  • 为什么 register / L1 / L2 / L3 延迟差这么多？ 物理距离 + 工艺：寄存器在 ALU 旁边（0 周期），L1 几 mm 内（4 周期），DRAM 离 CPU 几 cm（200 周期）。光速也是有限的。
  • "Aware of cache" 在实际代码里怎么体现？ (1) 选对循环顺序使内层是 stride-1；(2) 大矩阵用 blocking / tiling 让一个 block 装得下；(3) 数据结构对齐到 64 B；(4) 把热数据放小数组而不是大稀疏结构。
  • Row-major 还是 Column-major？ C/C++/NumPy 默认 row-major；Fortran/MATLAB/BLAS 是 column-major。用哪门语言、调哪个库，决定你的循环顺序。
  • Case B 的 hit rate 是 75%，为什么不是 100%？ 每条 cache line 装 4 个 float，第一次访问每条 line 必然 miss（cold miss），8 行每行 2 条 line = 16 必要 miss / 64 总访问 = 25% miss → 75% hit。
  • SIMD vs MIMD 的区别？ SIMD = 一条指令操作向量（同一控制流）；MIMD = 多个核各自有控制流（多核 CPU、分布式集群）。SIMT 是 GPU 的 SIMD 包装。
本节课的硬干货（必带走）：
  1. 编译四阶段：preprocess → compile → assemble → link。.c → .i → .s → .o → 可执行。
  2. Memory hierarchy：register → L1 → L2 → L3 → DRAM → disk。每跨一层延迟 ×10 以上，cache 友好的代码 = 命中率高 = 跑得快。
  3. Locality 两类：temporal（短期重用）、spatial（邻近访问）。
  4. 循环顺序决定性能：row-major 下，把 stride-1 的下标放到最内层。矩阵乘 ikj > ijk。
  5. Latency vs Throughput：CPU 优 latency、GPU 优 throughput；选硬件取决于工作负载形状，不是哪个更"强"。
