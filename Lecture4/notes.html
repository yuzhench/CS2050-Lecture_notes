Slide 4 — Spack：加载课程的软件栈

[$] . ~/161588/spack/share/spack/setup-env.sh
[$] spack env activate -p CS-2050

逐行解释

  • . ~/161588/spack/share/spack/setup-env.sh —— "." 等价于 source，把脚本里的 shell 函数/变量加载到当前会话（不是 fork 一个子 shell）。这个脚本注册 spack 这个命令并把环境变量挂上去。
  • spack env activate -p CS-2050 —— 激活课程预装的 Spack environment，名字叫 CS-2050。
    • env activate 类似 conda 的 activate：让这个环境里的工具（特定版本的 gcc、cmake、openmpi 等）出现在 PATH 里。
    • -p = "prompt"：在 shell 提示符前显示环境名，提醒你正处于哪个 env。

为什么 HPC 用 Spack 而不是 apt / conda？

  • HPC 集群上同一个软件经常要装多个版本（不同编译器、不同 MPI 实现、不同 BLAS）—— apt/yum 装不了多版本，conda 不擅长 C++ 系工具链。
  • Spack 让每个 (name, version, compiler, dependencies) 组合都有自己独立的安装路径，不会互相覆盖；并且能精确复现"gcc-12.2 + openmpi-4.1 + openblas-0.3"这种组合。
  • 这是 HPC 中心的标配工具。

Slide 10 — Bits and Bytes：double 占多少？

选择题：double precision floating point 用多少 bit / byte？

  • 16 bit (2 B)? —— 不，这是 half float（fp16）
  • 32 bit (4 B)? —— 不，这是 single (float)
  • 64 bit (8 B)? —— 正确，IEEE 754 double
  • 128 bit (16 B)? —— 不，这是 quad-precision，大多数硬件不原生支持

为什么重要：决定一条 cache line（64 B）能装多少元素——8 个 double，或 16 个 float，或 32 个 short。后面 SIMD 的"一条指令操作多少元素"也由它决定（AVX-512 = 512 bit / 64 bit = 8 doubles）。

Slide 16–18 — Example 2：用代码把 cache 测出来

实验设计

想用实验证明 L1/L2/L3 真的存在，思路：

  1. 开一个大小为 S kB 的数组，反复地顺序遍历它（保证只测内存访问，不测计算）。
  2. 记录"每元素平均访问时间"。
  3. 把 S 从很小（几 kB）逐步增大到很大（几百 MB），画曲线。

读两张图

Slide 17：线性坐标轴——只能看到一个台阶在 ~32 kB 附近（L1 边界）。横轴 0–150 kB 太窄，看不到 L2 / L3。

Slide 18：双对数坐标轴（关键）——横轴从 1 kB 到 1 GB，能清楚看到三个台阶：

  • 数组 ≲ 32 kB：完全装进 L1，平均访问时间最小（~4 周期）。
  • 数组介于 ~32 kB 到 ~1 MB：超出 L1 但在 L2 里，时间上一档（~10 周期）。
  • 数组介于 ~1 MB 到 ~25 MB：超出 L2 但在 L3 里，时间再上一档（~50 周期）。
  • 数组 > ~25 MB：每次访问都打到 DRAM（~200 周期）。
💡 这张曲线是 cache 存在的直接证据。曲线的"台阶位置"就是各级 cache 的大小；"台阶高度"就是各级 latency 的比值。把 lscpu 报告的 L1/L2/L3 大小拿来验证，能 1:1 对上。编程时心里要有这张图——你的工作集（working set）落在哪一段，性能就由那一段的 latency 决定。

为什么对数坐标更有用

因为 cache 大小是几何级数增长（32 kB → 1 MB → 25 MB，每级 ×30+），延迟也是几何级数（4 → 10 → 50 → 200）。线性轴会把小尺度全压扁，对数轴让每一段都能看清。

Slide 19 — 矩阵乘 locality 复习（来自 Lecture 3）

// Implementation 1: i, j, k
for (int i = 0; i < N; ++i)
    for (int j = 0; j < N; ++j)
        for (int k = 0; k < N; ++k)
            C[i][j] += A[i][k] * B[k][j];

// Implementation 2: i, k, j
for (int i = 0; i < N; ++i)
    for (int k = 0; k < N; ++k)
        for (int j = 0; j < N; ++j)
            C[i][j] += A[i][k] * B[k][j];

Lecture 3 里已经详细比过两者的 locality。这里再列出来是为了 example-3 / example-4 真去测一下两种循环顺序在真实机器上的速度差异。结论复用：

  • Impl 1 的内层 B[k][j] 是 stride-N → cache 友好性差
  • Impl 2 的内层 B[k][j] 是 stride-1 → cache 友好

用 Example 2 的实验工具测一下两者，能看到 Impl 2 在大矩阵上快 3–10×——和 cache 曲线的预测一致。

Slide 20–23 — Example 3：SIMD Vectorization

SIMD 的核心想法

把"一条指令对一个标量做加法"扩展成"一条指令对一向量做加法"。硬件层：CPU 多出一组向量寄存器（zmm0..31, 512 bit 各），和一组vector ALU。

x86 SIMD 演进表（slide 22 要会读）

扩展寄存器宽度首发架构年份
MMX64 bit（仅整数）Pentium MMX1997
SSE / SSE2 / SSE3 / SSE4128 bitPentium III → Core 21999–2008
AVX / AVX2256 bitSandy Bridge / Haswell2011 / 2013
AVX-512512 bitSkylake-X / Cannon Lake2015–2019

核心算式：一个 AVX-512 寄存器同时装 8 个 double 或 16 个 float。一条 vaddpd 指令一次完成 8 个 double 加法，理论吞吐 ×8。

怎么知道自己 CPU 支持哪一档（slide 23）

[$] lscpu

在 Flags: 那一行找 sse2、avx、avx2、avx512f 等关键词。CS 2050 集群的 Skylake Xeon 支持到 AVX-512。

写 SIMD 代码时必须先查 flags——用了硬件不支持的指令就 SIGILL（非法指令）崩溃。

Slide 26–27 — Experimental：用 SSH 直连集群

为什么要"直连"

到这节课为止，连集群的方式是浏览器开 Open OnDemand → 它再给你一个 shell。这要走 Harvard 的 web 服务，不能脚本化。"实验性"功能：在本地机器上用 ssh 命令直接连到集群——这样可以 scp、rsync、用 VS Code Remote-SSH、写 ssh + tmux 工作流。

前置条件（slide 26）

  • Harvard VPN：集群只对哈佛网络开放。在校外要先连 Harvard VPN。
  • SSH key：
    • 密钥已经在集群上：~/.ssh/ 里就有。
    • 把私钥拷到本地（用 scp 从集群拉回来），按需要重命名。
    • 私钥要当密码对待，不能外泄；权限必须 chmod 600——SSH 检查到权限太松会拒绝使用。

本地 SSH config 写法（slide 27）

# ~/.ssh/config
Host CS-2050
  Hostname academ-acade-u490GFH4ghvP-2726a85b0a9f62fa.elb.us-east-1.amazonaws.com
  user wcw398
  IdentityFile ~/.ssh/CS-2050_id_rsa

逐行解释

  • Host CS-2050 —— 给这个连接起个短别名。以后 ssh CS-2050 就够了。
  • Hostname ... —— 真实的服务器地址（一个 AWS ELB 域名，说明集群其实跑在 AWS 上）。别名是给人看的，Hostname 才是给网络用的。
  • user wcw398 —— 登录用的用户名（讲师的 NetID）。每个人要换成自己的。
  • IdentityFile ~/.ssh/CS-2050_id_rsa —— 用哪个私钥。如果有多把 key，必须显式指定，否则 SSH 默认按 id_rsa 试一遍可能不对。

配好之后，本地连接：

$ ssh CS-2050

就能直接落地到 login node。文件传输：

$ scp some_file.txt CS-2050:~/        # 本地 → 集群
$ scp CS-2050:~/result.dat ./         # 集群 → 本地
$ rsync -avz ./code/ CS-2050:~/code/  # 同步整目录
💡 一旦 SSH 直连配好，整套本地编辑 + 远程执行工作流就解锁了：VS Code Remote-SSH、rsync 部署、ssh + tmux 后台跑任务、git 直接 push 到集群 bare repo……几乎所有 HPC 用户的日常都在用这套。
📌 Q&A 补充要点（点击展开）
  • Spack 和 conda 的区别？ conda 主要管 Python 包；Spack 主要管 C/C++/Fortran 系科学软件，能精确指定编译器和依赖图。HPC 大量用 Spack 是因为它能让"用 gcc-12 编的 OpenMPI" 和 "用 intel 编的 OpenMPI" 并存。
  • 双对数图为什么能看出 cache 边界？ 因为 cache 大小和延迟都是几何级数变化的，log-log 把每一段拉成等宽，台阶在视觉上清楚。线性图会被最大那段（DRAM）压扁。
  • AVX-512 一条加法操作多少元素？ 512 bit / 64 bit = 8 个 double，或 / 32 bit = 16 个 float。理论加速上限就是这个倍数（实际受 memory bandwidth 限制）。
  • 没有 AVX-512 的 CPU 怎么办？ 退到 AVX2（256 bit，4 double / 8 float）。编译器加 -mavx2 或 -march=native 自动选最高支持档。
  • SSH key 权限 600 是什么意思？ 只有 owner 可读可写，group / other 都没权限。SSH 会拒绝读权限过松的私钥（防止你不小心把 key 留在共享目录被别人偷）。
  • Hostname 那串 AWS ELB 是什么？ Elastic Load Balancer——一个域名后面挂多台 login node，连进去 ELB 会分流。所以你每次连可能落到不同的物理节点，但用户体验一致。

  2. Cache 是可测量的：log-log 时间 vs 数组大小曲线上有 3 个台阶，对应 L1/L2/L3 边界。编程时心里要有这张图。
